\titulo{2. Colección canónica LR(1)}
\section*{Reglas de construcción}
Un ítem es $[A\to\alpha\cdot\beta,a]$. En los datos se representa como \texttt{[produccion, posicion, lookahead]}; la posición indica cuántos símbolos del RHS están antes del punto.
\[
I_0=\operatorname{CLOSURE}(\{[\texttt{Start}\to\cdot\texttt{Program},\$]\}).
\]
Para $[A\to\alpha\cdot B\beta,a]$, CLOSURE agrega $[B\to\cdot\gamma,b]$ por cada producción $B\to\gamma$ y cada $b\in\operatorname{FIRST}(\beta a)$. Repetir hasta no agregar ítems. GOTO mueve el punto sobre el símbolo y cierra el resultado. Solo se crea un estado nuevo si el conjunto completo de ítems LR(1) es distinto.

\begin{lstlisting}
I0 = { [Start -> . Program, $],
       [Program -> . int main ( ) Block, $] }
GOTO(I0, int) = I2
GOTO(I0, Program) = I1
I1 = { [Start -> Program ., $] }  // aceptacion
\end{lstlisting}
En I28 aparece \texttt{Decl -> Type ID . Init ;}. CLOSURE usa $\operatorname{FIRST}(\texttt{;}a)=\{\texttt{;}\}$ y agrega \texttt{Init -> . = Expr} e \texttt{Init -> .}, ambos con lookahead \texttt{;}.
\section*{Elección de CLR(1)}
Se mantiene el método acordado: construir la colección canónica, calcular FIRST($\beta a$) y conservar los lookaheads de cada estado. No se fusionan estados por núcleo LR(0). La colección mantiene los lookaheads propios de cada estado, conforme al método CLR(1) acordado para el proyecto.
\section*{Resultado}
161 estados alcanzables y distintos; 730 transiciones. El ítem de aceptación está en I1. Un ítem con posición igual a la longitud del RHS está completo; p0 es aceptación y las demás producciones generan reducciones bajo su lookahead.

\section*{Ejemplo de CLOSURE y GOTO en I28}
Se parte del ítem \texttt{[Decl -> Type ID . Init ;, a]}. El no terminal después del punto es Init; la secuencia que queda después de él es \texttt{;}. Por tanto:
\[
B=\texttt{Init},\qquad\beta=\texttt{;},\qquad
\operatorname{FIRST}(\beta a)=\operatorname{FIRST}(\texttt{;}a)=\{\texttt{;}\}.
\]
\begin{enumerate}
\item Consultar las dos producciones de Init: p11 y p12.
\item Agregar \texttt{[Init -> . = Expr, ;]} y \texttt{[Init -> ., ;]}.
\item El primer ítem permite avanzar con \texttt{=} hasta I49. El segundo ya está completo porque p12 tiene RHS vacío: permite reducir únicamente ante \texttt{;}.
\item Al reconocer Init, GOTO(I28,Init) lleva a I50 y el ítem de Decl queda como \texttt{Decl -> Type ID Init . ;}.
\end{enumerate}
La anticipación \texttt{;} de los ítems añadidos proviene de FIRST($\beta a$). No se obtiene copiando sin más \texttt{a}, ni calculando FOLLOW(Init).
\section*{Qué pasa si la secuencia puede ser vacía}
Al entrar al bloque, I7 contiene \texttt{[Block -> \{ . Items \}, \$]}. Al expandir Items se usa FIRST de \texttt{\}\$}, cuyo único inicio es \texttt{\}}. Por eso aparecen inicialmente ítems de Items con ese lookahead.

Después, \texttt{[Items -> . Items Item, \}]} vuelve a expandir Items. Esta vez se calcula FIRST(\texttt{Item}\texttt{\}}): se añaden los posibles inicios de Item. La repetición de CLOSURE reúne todos esos contextos hasta llegar al punto fijo. Si una secuencia $\beta$ es anulable, el cálculo debe continuar hasta \texttt{a}; si $\beta$ está vacía, FIRST($\beta a$) es \{a\}.
\section*{Por qué no se eliminan estados de igual núcleo}
I9 e I122 contienen el mismo núcleo \texttt{Simple -> ; .}. Sin embargo, I122 incluye el lookahead \texttt{else} e I9 no. En I122 se puede reducir p24 al ver else; en I9 esa reducción no está autorizada. Son estados CLR(1) distintos, aunque su parte LR(0) coincida.
\section*{Cómo leer la colección compacta}
\texttt{(12,0,L3)*} significa p12, punto en posición cero y todos los lookaheads de L3. Como p12 es vacía y L3 contiene solo \texttt{;}, equivale a \texttt{[Init -> ., ;]}. El asterisco marca que está completo. En cambio, \texttt{(7,2,L1)} tiene dos símbolos reconocidos de \texttt{Decl -> Type ID Init ;}: el punto está después de ID.

Los conjuntos L0--L13 solo evitan repetir listas de lookaheads en el documento. Cada estado sigue representando su conjunto completo de ítems LR(1), sin fusión de estados.
